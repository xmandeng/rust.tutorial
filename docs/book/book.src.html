1 What Rust Is

Rust is a statically typed, compiled systems language. It started at Mozilla, reached version 1.0 in 2015, and is now run by the Rust Foundation. "Statically typed" means every variable's type is fixed and checked when the program is compiled, before it runs. "Compiled" means the compiler turns your source into a native executable for one kind of machine: there is no interpreter and no virtual machine.

Rust's selling point is that it is as fast as C and C++ but prevents their most common bugs at compile time: using memory after it was freed, freeing it twice, reading past the end of an array, and two threads changing the same data at once. It does this without a garbage collector, through a set of rules called ownership (chapter 6).

Python developers meet Rust more often than they realise. uv, ruff, polars and pydantic-core (the engine inside Pydantic 2) are written in Rust and called from Python through a library named PyO3. "Rewrite the hot loop in Rust" is now a common answer to "this Python is too slow".

1.2  How a Rust Program Runs

cargo build runs the compiler, which checks every type, every borrow and every match in every file, and refuses to produce a program if any check fails. The output is a native executable in target/debug/. Running it needs nothing else installed: no Rust, no runtime, no interpreter.

Python finds a type mistake only when the faulty line runs. Rust finds it, and a whole class of memory and threading mistakes, before the program can start. The cost is a slower edit-compile cycle and a compiler that says no often. Rust developers describe this as "fighting the borrow checker" while learning, and "if it compiles, it usually works" afterwards.

Figure 1. Python checks types while running; Rust checks types and memory use before running.

1.3  Editions and Releases

A new stable Rust version ships every six weeks, and old code keeps compiling. Larger changes arrive through editions: 2015, 2018, 2021 and 2024. Each crate names its edition in Cargo.toml, and crates of different editions work together. The companion project uses the 2024 edition. Code written for 2018 or 2021 looks almost the same; section 9.3 points out the one piece of 2024-only syntax the project uses.

2.3  Cargo.toml

Cargo.toml lists a package's name, edition and dependencies. It is the counterpart of pyproject.toml. The root one, without its comments:

:::toml Cargo.toml [package] name = "tutorial" version = "0.1.0" edition = "2024" rust-version = "1.88" [dependencies] serde = { version = "1.0.229", features = ["derive"] } tokio = { version = "1.54.1", features = ["rt-multi-thread", "macros", "time"] } [workspace] members = ["api"] :::
  • edition: which edition's rules this crate follows (section 1.3).
  • rust-version: the oldest Rust that can build it (Python: requires-python). An older compiler stops with a message naming the version needed.
  • [dependencies]: crates from crates.io. "1.0.229" means "1.0.229 or any later 1.x version" (Python: >=1.0.229,<2); Cargo.lock records the exact version chosen.
  • features: optional parts of a crate to switch on, like Python extras (pip install "fastapi[all]"). serde's derive feature is used in chapter 15; tokio is used in chapter 14.
  • [workspace]: adds api/ as a second package.

2.4  Modules: lib.rs and main.rs

A Rust package can hold a library (src/lib.rs) and a program (src/main.rs). The program uses the library like any outside code would. Each pub mod name; line in lib.rs tells the compiler to include the file src/name.rs (or src/name/mod.rs) as a module. A module is Python's module: a namespace, one per file. Unlike Python, files are not found automatically; a file nobody declares with mod is not compiled.

:::file src/lib.rs :: pub mod ch03_basics ..> pub mod orders

pub makes an item public. Everything in Rust is private to its module unless marked pub, and the compiler enforces it. Python's leading underscore is only a convention.

2.5  main.rs Walkthrough

main.rs reads the command line and calls each chapter's run function. It uses syntax from the next few chapters; skim it now and return to it after chapter 6. Execution starts at fn main(), as Python starts at if __name__ == "__main__":.

3 Syntax Basics

This chapter covers what every Rust file looks like: functions, variables, printing and blocks. File: src/ch03_basics.rs. Run it with cargo run -- 3.

3.1  The Whole File

:::file src/ch03_basics.rs :: pub fn run() :: fn square :::out Ada published the first program in 1843. count is 1 price 19.99, padded [ 1843], debug "Ada" Hello, Ada! is 11 bytes long a year later it was 1844 area is 12 square(7) is 49 :::

3.2  Reading It

  • fn defines a function (Python: def). pub makes it callable from other modules; square has no pub, so only this file can call it.
  • let creates a variable. Its type is inferred from the value, but it is still fixed: year is an i32 (32-bit integer) forever.
  • Immutable by default. A plain let variable cannot be changed. let mut allows changes. Python has no equivalent; the closest is a naming convention for constants.
  • Formatting. println!("{name}") is Python's print(f"{name}"). Format specs follow a colon, as in Python: {price:.2}, {year:>8}. {:?} prints the debug form, which for a string includes the quotes, like repr(). {} with an argument after the string fills in an expression.
  • Shadowing. let year = year + 1; makes a new variable that hides the old one. It is common in Rust, for example to convert a value and keep the same name.
  • Blocks are expressions. The value of a { } block is its last expression, written without a semicolon. square returns n * n this way. A return keyword exists, but is used only to leave a function early.
  • Types in signatures are required. fn square(n: i32) -> i32 is Python's def square(n: int) -> int, except the compiler enforces it.
The semicolon matters. n * n is a value; n * n; is a statement that throws the value away. Adding a stray semicolon to the last line of a function is a common beginner error; drill 2 shows the message it produces.

4.2  Two String Types

:::file src/ch04_types.rs :: let mut owned: String ..> owned.split :::out hello, world / literals are &str upper: HELLO, WORLD, words: 2 :::

This confuses every newcomer, and interviewers ask about it.

  • String owns its text, stored on the heap. It can grow (push_str). Create one with String::from("..."), "...".to_string() or format!.
  • &str ("string slice", said "stir" or "string ref") is a borrowed view of text owned by something else: a String, or the program file itself for a literal such as "world". It cannot grow.
  • Function parameters are usually &str, because a &String converts to a &str automatically, so the function accepts both. Struct fields are usually String, because the struct should own its data.
  • Both are always valid UTF-8. s[0] does not compile, because one character can be several bytes. Use s.chars() to walk characters.

Chapter 6 explains the words "own" and "borrow". Python has one str type because its garbage collector decides when text is freed; in Rust, the type says who is responsible.

4.3  Tuples and Arrays

:::file src/ch04_types.rs :: let point: ..> primes.len() :::out x=3 y=4.5 first prime=2 count=4 :::

Tuples work as in Python, including unpacking with let (x, y) = point;. Access one field with point.0. An array [i32; 4] has a fixed length that is part of its type; the growable list is Vec (chapter 10). Indexing past the end of either stops the program with a panic instead of reading random memory.

4.4  No Null: Option

:::file src/ch04_types.rs :: // No null. ..> z_at.unwrap_or(0) :::out Some(7) None z found? false, z position or 0: 0 :::

Rust has no None/null that any variable might hold. A value that may be missing has the type Option<T>, which is either Some(value) or None. Option<usize> and usize are different types, so you cannot use a possibly-missing number as if it were present; the compiler makes you handle None first. Python's Optional[int] hint says the same thing, but nothing enforces it. Chapter 8 shows how to take an Option apart with match; chapter 9 shows its helper methods.

5 Control Flow

Rust has if, match, and three loops: for, while and loop. Conditions need no parentheses, but the braces are required. File: src/ch05_control_flow.rs.

5.1  if Is an Expression

Because if produces a value, Rust needs no separate conditional expression; this is Python's "hot" if t > 25 else .... Every branch must produce the same type. The condition must be a bool: if count with a number does not compile, where Python would test for non-zero.

6 Ownership and Borrowing

Ownership is the idea that makes Rust different from every language you know, and the topic an interviewer is most likely to probe. It replaces the garbage collector. File: src/ch06_ownership.rs.

6.1  The Three Rules

  1. Each value has one owner: the variable (or struct field, or collection) that holds it.
  2. There is only one owner at a time. Assigning or passing the value moves ownership.
  3. When the owner goes out of scope (its closing }), the value is dropped: its memory is freed, immediately and deterministically.

In Python, b = a makes two names for one object, and the garbage collector frees the object some time after the last name disappears. In Rust, let b = a; hands the value to b, and a may not be used again. Because exactly one owner exists, the compiler knows exactly where to free the memory, and no garbage collector is needed.

Figure 3. A move transfers the owner; a borrow lends access while the owner keeps the value.

6.2  Moves, Clones and Copies

:::file src/ch06_ownership.rs :: // 1. Move ..> println!("the function took :::file src/ch06_ownership.rs :: fn take_ownership :::out b = report.pdf b = report.pdf, c = report.pdf x = 5, y = 5 the function took a title of 13 bytes :::

Move. After let b = a;, using a is a compile error. Remove the // in front of println!("{a}") and cargo build reports:

:::out cargo build error[E0382]: borrow of moved value: `a` --> src/ch06_ownership.rs:7:16 | 5 | let a = String::from("report.pdf"); | - move occurs because `a` has type `String`, which does not implement the `Copy` trait 6 | let b = a; | - value moved here 7 | println!("{a}"); | ^ value borrowed here after move | help: consider cloning the value if the performance cost is acceptable | 6 | let b = a.clone(); | ++++++++ :::
  • Clone. .clone() makes an independent deep copy (Python: copy.deepcopy). It costs time and memory, so Rust never does it implicitly.
  • Copy. Small fixed-size types (integers, floats, bool, char, and tuples of them) implement the Copy trait. Assigning them copies the bits and both variables stay usable, as x and y show.
  • Passing to a function moves too. take_ownership(title) moves the String into the function, which frees it when it returns. Afterwards title is unusable in run.

Read the compiler error above line by line. Rust's errors name the rule, point at each line involved and often suggest the fix. rustc --explain E0382 prints a longer explanation with examples.

6.3  Borrowing

Moving everything into functions would be impractical, so Rust lets you borrow: create a reference that gives access to a value without taking ownership.

:::file src/ch06_ownership.rs :: // 5. Borrow ..> println!("log = :::file src/ch06_ownership.rs :: fn count_words :: fn add_entry :::out 'Quarterly Report for Q3' has 4 words log = ["started", "finished"] :::
  • &doc creates a shared reference (type &String, accepted as &str). The function can read but not change the value.
  • &mut log creates a mutable reference. The function can change the caller's vector. Both the variable (let mut log) and the borrow (&mut) must say mut, so a reader can see every place a value might change.
  • When the function returns, the borrow ends and the owner has full control again.

In Python every argument is passed by reference and any function can change a mutable argument. In Rust the signature says which: T (takes ownership), &T (reads), &mut T (changes).

6.4  The Borrow Rule

At any moment, a value may have either any number of shared references or exactly one mutable reference, never both. And no reference may outlive the value it points to.

:::file src/ch06_ownership.rs :: // 7. The borrow rule ..> println!("scores :::out first = 10 scores = [10, 20, 30, 40] :::

Why the rule exists: push may move the vector's contents to a bigger block of memory. If that happened while first still pointed into the old block, first would point at freed memory. In C++ that is a real, common bug. Rust rejects the program instead. Move the push above the println! that uses first, and the compiler says:

:::out cargo build error[E0502]: cannot borrow `scores` as mutable because it is also borrowed as immutable --> src/ch06_ownership.rs:39:5 | 38 | let first = &scores[0]; | ------ immutable borrow occurs here 39 | scores.push(40); | ^^^^^^^^^^^^^^^ mutable borrow occurs here 40 | // // because it is also borrowed as immutable 41 | println!("first = {first}"); | ----- immutable borrow later used here :::

A borrow lasts only until its last use, not to the end of the block, so the final push in the file is allowed. The part of the compiler that checks these rules is the borrow checker.

In one sentence. Ownership means every value has one owner that frees it at the end of its scope; borrowing lends access through references, with many readers or one writer at a time, and the compiler checks all of it, so Rust is memory-safe without a garbage collector.

7 Structs and Methods

Rust has no classes. A struct holds data, and an impl block attaches methods to it. Together they do most of what a Python class does, without inheritance (chapter 11 covers what replaces it). File: src/ch07_structs.rs.

7.1  A Struct: BankAccount

BankAccount shows encapsulation: the data is private, and outside code can change it only through methods that check each change. Money is held as whole cents in an i64, never as a float; 120_00 is 120.00 written so the cents stand out.

:::file src/ch07_structs.rs :: pub struct BankAccount :: impl BankAccount

The same class in Python, for comparison:

:::py class BankAccount: def __init__(self, id: str, owner: str): self.id = id self.owner = owner self._balance_cents = 0 @property def balance(self) -> int: return self._balance_cents def deposit(self, cents: int) -> None: if cents <= 0: raise ValueError(f"deposit must be positive, got {cents}") self._balance_cents += cents :::

7.2  Reading the Struct

  • Fields are declared once, with types, in the struct. Without pub they are private to this module. Python's _balance is a convention; Rust's privacy is enforced.
  • impl BankAccount { ... } holds the methods. A type can have several impl blocks.
  • new is an associated function: it has no self, so it is called on the type, BankAccount::new(...). Rust has no constructor keyword; new is a naming convention. The struct literal BankAccount { id: ..., owner: ..., balance_cents: 0 } builds the value.
  • The three kinds of self are chapter 6's rules applied to methods: &self borrows the object to read it (balance), &mut self borrows it to change it (deposit), and plain self takes ownership, consuming the object. Python's self is always the first kind and the second at once.
  • Errors are return values. deposit returns Result<(), String>: either Ok(()) (success, no value; () is the empty tuple, Rust's "nothing") or Err(message). Chapter 9 covers this fully.
  • #[derive(Debug)] is an attribute that generates code: here, the ability to print the struct with {:?}.

7.3  Using It

:::file src/ch07_structs.rs :: let mut account = BankAccount ..> println!("{account:?} :::out ACC-0001 Ada: 120.00 Refused: insufficient funds: balance 120.00, requested 500.00 Refused: deposit must be positive, got -5 Ada now has 100.00 BankAccount { id: "ACC-0001", owner: "Ada", balance_cents: 10000 } :::

  • .unwrap() takes the success value out of a Result and stops the program if it was an error. Fine in demos and tests, where an error means a bug.
  • match handles both outcomes; if let Err(message) = ... handles only the error. Both are chapter 8's pattern matching.

8 Enums and Pattern Matching

A Rust enum is a type whose value is exactly one of a fixed list of variants, and each variant can carry its own data. Python's enum.Enum covers only the simplest case. Together with match, enums are how Rust code models "one of these things". File: src/ch08_enums.rs.

9 Error Handling: Result and Option

Rust has no exceptions. A function that can fail returns Result<T, E>, an enum with two variants: Ok(T) holding the value, or Err(E) holding the error. The failure is part of the function's type, so callers cannot forget it exists. File: src/ch09_errors.rs.

9.1  Handling a Result

:::file src/ch09_errors.rs :: fn parse_age

The Python equivalent:

:::py def parse_age(text: str) -> int: try: return int(text.strip()) except ValueError as e: raise ValueError(f"'{text}' is not an age: {e}") :::

parse::<u32>() converts text to a number and returns Result<u32, ParseIntError>. The ::<u32> ("turbofish") tells it which number type to produce. The match handles both variants; returning Err(...) is the Rust form of raise.

9.2  The ? Operator

:::file src/ch09_errors.rs :: fn sum_numbers :::out Ok(6) could not sum: invalid digit found in string :::

expr? means: if expr is Ok(v), the expression's value is v; if it is Err(e), return Err(e) from this function now. It is how an error travels up the call stack, the job an uncaught exception does in Python, but every place it can happen is marked with a visible ?. It works only inside a function that itself returns a Result (or an Option, where it returns None early). When the error types differ, ? converts the error with the From trait if a conversion exists.

9.3  A Custom Error Type

Real code defines its own error enum, one variant per way the operation can fail. A caller can then match on the variant, which is Python's except with several exception classes.

:::file src/ch09_errors.rs :: pub enum ConfigError :: impl fmt::Display for ConfigError :: impl std::error::Error :::file src/ch09_errors.rs :: fn find_setting :: pub fn read_port :::out port 5432 config error: setting 'port' is missing config error: setting 'port' should be a number, got 'http' config error: setting 'port' is out of range: 70000 :::

  • impl std::error::Error for ConfigError {} marks it as an error type; the trait's methods all have defaults, so the block is empty. Chapter 11 explains traits.
  • ok_or(...) turns an Option into a Result: None becomes the given error, which ? then returns.
  • if let Some((k, v)) = ... && k.trim() == key needs the 2024 edition. In older code you will see two nested ifs instead.
  • Libraries named thiserror (for defining error enums) and anyhow (for applications that only report errors) remove most of this boilerplate. Interviewers often mention them.

9.4  Panics and Shortcuts

11 Traits and Generics

A trait is a named set of methods that a type promises to provide. It is Rust's answer to interfaces, abstract base classes and Python's Protocol. Rust has no inheritance between structs: shared behaviour comes from traits, and shared data from putting one struct inside another (composition). File: src/ch11_traits.rs.

11.1  Defining and Implementing a Trait

:::file src/ch11_traits.rs :: pub trait Describe :: pub struct Dog ..> impl Describe for Robot
  • fn name(&self) -> String; ends in a semicolon: it has no body, so every implementing type must write one. Python: an @abstractmethod.
  • describe has a body, a default method. Dog replaces it; Robot keeps it.
  • impl Describe for Dog is written separately from the struct. You can implement your own trait for someone else's type, or someone else's trait for your type, but not someone else's trait for someone else's type (the orphan rule).
  • Python's Protocol is matched by shape: any class with a name method fits. A Rust type fits a trait only with an explicit impl.

11.2  Generics: Static Dispatch

:::file src/ch11_traits.rs :: pub fn announce :: pub fn largest

The compiler checks the bound where the function is called, and generates a separate copy of announce for each type it is used with (monomorphisation). The call is then as fast as a direct call. largest has two bounds joined by +: PartialOrd allows >, Copy allows let mut best = items[0] without moving out of the slice.

13 Lifetimes and Smart Pointers

This chapter finishes the ownership story: how the compiler tracks how long a reference is valid, what happens when a value is dropped, and the types to reach for when one owner is not enough. File: src/ch13_lifetimes.rs.

13.1  Lifetimes

A lifetime is the span of code during which a reference is valid. The compiler checks that no reference outlives the value it points to (the second half of section 6.4's rule). Usually it works the lifetimes out alone. When a function returns a reference and takes more than one, it cannot tell which input the result borrows from, and you must say:

:::file src/ch13_lifetimes.rs :: fn longest :: pub struct Headline :: impl<'a> Headline
  • 'a (said "tick a" or "lifetime a") is a lifetime parameter, declared in angle brackets like a type parameter. longest<'a>(x: &'a str, y: &'a str) -> &'a str says: the result is valid as long as both inputs are.
  • Lifetime annotations do not change how long anything lives. They describe relationships so the compiler can check the callers.
  • A struct that holds a reference needs a lifetime parameter too: a Headline may not outlive the text it points into. Most structs avoid this by owning their data (String, not &str).
  • 'static is the lifetime of the whole program. String literals are &'static str.
:::file src/ch13_lifetimes.rs :: let a = String::from ..> println!("first word :::out longest: a much longer line first word: Rust :::

Moving the println!("longest: ...") line below the inner block's closing brace is a compile error: b is dropped at that brace, and result might point into it.

13.2  Drop: Cleanup at Scope End

:::file src/ch13_lifetimes.rs :: pub struct Resource :: impl Drop for Resource :::file src/ch13_lifetimes.rs :: println!("before the block") ..> println!("after the block") :::out before the block using both closing database closing data.csv after the block :::

The drop method of the Drop trait runs automatically when a value's owner goes out of scope, in reverse order of creation. Rust's File, MutexGuard and network connections use it to close or release themselves, so Rust needs no with statement and no finally. The pattern is called RAII ("resource acquisition is initialisation"), a name taken from C++.

13.3  Box: Values on the Heap

:::file src/ch13_lifetimes.rs :: pub enum Expr :: pub fn eval :::file src/ch13_lifetimes.rs :: let expr = Expr::Mul ..> println!("(2 + 3) :::out (2 + 3) * 4 = 20 :::

Every Rust type must have a size known at compile time. An Expr that contained an Expr directly would be infinitely large. Box<Expr> is a pointer to an Expr on the heap, so its size is fixed. Box has one owner and frees its contents when dropped. It is also how you store a trait object (Box<dyn Describe>, section 11.3).

13.4  Rc and RefCell: Shared Ownership

:::file src/ch13_lifetimes.rs :: // Rc: ..> Rc::strong_count :::out shared = [1, 2, 3], owners = 2 :::

Sometimes one owner is not enough: a graph node with several parents, or a cache shared by several parts of a program. Rc<T> (reference counted) allows several owners. Rc::clone copies the pointer, not the data, and adds one to a counter; the value is freed when the counter reaches zero. This is exactly how CPython manages memory.

Rc gives only shared (read-only) access. RefCell<T> allows changing the value through a shared reference by moving the borrow check from compile time to run time: borrow_mut() panics if the value is already borrowed. This is called interior mutability.

TypeUse when
Box<T>One owner, value on the heap: recursive types, trait objects

Common pairings are Rc<RefCell<T>> in single-threaded code and Arc<Mutex<T>> in multi-threaded code. Two Rcs that point at each other are never freed (a leak); Weak pointers break such cycles.

14 Concurrency and Async

Rust's ownership rules also prevent data races: two threads touching the same data at once with at least one writing. A program with a possible data race does not compile. Rust calls this "fearless concurrency". File: src/ch14_concurrency.rs.

14.1  Threads

:::file src/ch14_concurrency.rs :: // 1. Threads ..> println!("sum of :::out sum of 1..=1000 over 4 threads: 500500 :::
  • thread::spawn starts an operating-system thread running the closure and returns a JoinHandle. join() waits for it and returns the closure's result. Python: threading.Thread, or concurrent.futures.
  • There is no GIL. The four threads run on four cores at once, which is why CPU-heavy Python work moves to Rust.
  • move makes the closure take ownership of chunk. Without it the closure would borrow a local variable that might be gone before the thread finishes, and the compiler refuses.

14.2  Shared State: Arc and Mutex

:::file src/ch14_concurrency.rs :: let counter = Arc::new ..> "counter after :::out counter after 8 threads x 1000: 8000 :::
  • Mutex<i32> wraps the data it protects. The only way to reach the number is lock(), so you cannot forget to lock. Python's threading.Lock is separate from the data, and nothing stops code touching the data without it.
  • lock() returns a guard. The lock is released when the guard is dropped, here at the end of the statement (section 13.2).
  • lock() returns a Result because a thread that panicked while holding the lock leaves it "poisoned". unwrap() passes that panic on.
  • Arc is the thread-safe Rc. Each thread gets its own Arc pointing at the same Mutex.

The compiler enforces this with two marker traits. Send: the type may be moved to another thread. Sync: the type may be shared between threads by reference. Rc is neither, so trying to pass an Rc to thread::spawn is a compile error; Arc is both.

14.3  Channels

:::file src/ch14_concurrency.rs :: let (sender, receiver) ..> println!("received :::out received [10, 20, 30] :::

A channel sends values from threads to a receiver, like Python's queue.Queue. mpsc stands for "multiple producer, single consumer". Sending moves the value, so the sender can no longer touch it: no sharing, so no lock is needed. The receiver's loop ends when every sender has been dropped. The results are sorted because the threads may finish in any order.

14.4  Async and Await

:::file src/ch14_concurrency.rs :: let runtime = tokio ..> runtime.block_on :: async fn fetch :: async fn fetch_both :::out got prices (200 ms) and news (100 ms) waited under 300 ms, not 200 + 100: true :::

The syntax matches Python's: async fn and .await (written after the expression). The differences matter in an interview:

  • No built-in runtime. Python ships asyncio. Rust's standard library defines futures but no event loop to run them; you choose a crate. Tokio is the de facto standard, and the web API in chapter 16 runs on it. runtime.block_on(...) is asyncio.run(...); in a program whose main is async, the #[tokio::main] attribute does the same.
  • Futures are lazy. Calling fetch(...) does nothing until the result is awaited or passed to something like join!. A Python coroutine is also lazy, but asyncio.create_task schedules it to run straight away.
  • tokio::join! runs both futures concurrently and waits for both: asyncio.gather. tokio::spawn starts an independent task: asyncio.create_task.
  • Tokio's default runtime spreads tasks across several threads, so the data a task uses must be Send. Python's event loop is single-threaded.
  • Use async for many waits at once (network servers, many HTTP calls); use threads for CPU-heavy work. This is the same rule as in Python.

Ownership changes the design compared with Python or C#. There, the caller and the service could both hold the same inventory object. Here, new moves the inventory into the service, and the service is its only owner. Other code reaches it by borrowing through inventory() (read) or inventory_mut() (change). 16 Walkthrough: The Web API

Rust web back ends are usually built with axum (from the Tokio team) or actix-web. axum's style resembles FastAPI or Flask: you map a URL to an async function. The package in api/ serves the order system over HTTP in about 120 lines. Its Cargo.toml lists axum, tokio, serde, serde_json, and the tutorial library by path.

16.1  Shared State

:::file api/src/main.rs :: struct AppState :: type SharedState

Requests are handled concurrently, on several threads. Every handler needs the catalog and the order service, and the service changes on every order. Chapter 14's rules decide the design:

  • The whole state sits in an Arc, so every request can hold a pointer to it.
  • What changes (the service, the order counter) sits in a Mutex; what never changes (the catalog) does not need one.
  • type SharedState = Arc<AppState>; is a type alias, a short name for a long type.

Replace the Mutex with chapter 13's single-threaded RefCell, and the program does not compile: "RefCell<OrderService<BulkDiscount>> cannot be shared between threads safely". In Python the same mistake compiles, runs, and corrupts stock counts under load.

16.3  Handlers

  • Extractors. Each handler parameter says where its value comes from: State(state) from the shared state, Path(sku) from the URL, Json(request) from the JSON body. FastAPI reads type hints the same way. A body that does not fit OrderRequest is rejected with HTTP 422 before the handler runs.

  • let Some(product) = ... else { return ...; }; is let-else: bind the value if the pattern matches, otherwise run the else block, which must leave the function.
  • json!({ ... }) builds a JSON value with Python-dict-like syntax.
  • The order-number block { let mut next = ...; ... } releases its lock at its closing brace (section 13.2), before checkout takes the other lock.

18 Interview Quick Reference

Each answer below is short enough to say aloud. Each one points to the example in the companion project that you can describe.

18.1  Likely Questions

How does Rust guarantee memory safety without a garbage collector?

Ownership. Every value has one owner, and it is freed when the owner goes out of scope. Values can be borrowed through references, with either many shared references or one mutable reference at a time, and no reference may outlive its value. The compiler's borrow checker enforces these rules, so use-after-free, double free and data races do not compile. (Chapter 6.)

What is the difference between a move, a copy and a clone?

A move transfers ownership; the old variable can no longer be used. Types that implement Copy (numbers, bool, char) are copied bit for bit on assignment instead, and both stay usable. clone() is an explicit, possibly expensive deep copy. Rust never clones implicitly. (Section 6.2.)

What is a lifetime?

The span of code during which a reference is valid. The compiler infers most lifetimes. When a function returns a reference derived from several inputs, you annotate the relationship, as in fn longest<'a>(x: &'a str, y: &'a str) -> &'a str. Annotations describe constraints; they never extend how long anything lives. (Section 13.1.)

String versus &str?

String owns heap-allocated, growable UTF-8 text. &str is a borrowed view of text owned elsewhere, such as a String or a literal. Take &str in function parameters; store String in structs. (Section 4.2.)

How does Rust handle errors? Why no exceptions?

Recoverable errors are values: functions return Result<T, E>, and the ? operator passes an error up to the caller. The possible failure is part of the signature, so it cannot be ignored by accident. Bugs cause a panic, which stops the thread. Missing values use Option<T> instead of null. OrderService::checkout returning Result<Receipt, OrderError> is the example. (Chapter 9.)

unwrap versus expect versus ?

unwrap panics on an error; expect panics with your message; ? returns the error to the caller. Use ? in library and application code, expect where an error is truly impossible or in main, and unwrap mainly in tests.

What is a trait? How does Rust do object-oriented programming?

A trait is a set of methods a type promises to implement, like an interface, and it can supply default methods. Rust has encapsulation (private fields, pub), polymorphism (traits) and abstraction, but no inheritance between structs: shared behaviour comes from traits and shared data from composition. DiscountPolicy with NoDiscount and BulkDiscount is the example. (Chapter 11.)

Generics versus trait objects? Static versus dynamic dispatch?

A generic fn f<T: Trait> is compiled separately for each concrete type (monomorphisation): static dispatch, fastest, but one type per use. A trait object Box<dyn Trait> calls through a vtable at run time: dynamic dispatch, slightly slower, but one collection can hold different types. OrderService<D: DiscountPolicy> uses a generic; Vec<Box<dyn Describe>> uses trait objects. (Sections 11.2, 11.3.)

Enums and match: why are they important?

Rust enums are sum types: a value is exactly one variant, and each variant can carry different data. match must handle every variant, so adding a variant turns every place that forgot it into a compile error. Option, Result and OrderError are all enums. (Chapter 8.)

Box, Rc, Arc, RefCell, Mutex: when do you use each?

Box: one owner, value on the heap (recursive types, trait objects). Rc: several owners in one thread. Arc: several owners across threads. RefCell: mutation through a shared reference in one thread, checked at run time. Mutex: the same across threads, one at a time. The web API's Arc<AppState> holding a Mutex<OrderService> is the example. (Sections 13.4, 16.1.)

What are Send and Sync? What is fearless concurrency?

Send: a value can move to another thread. Sync: a value can be shared between threads by reference. The compiler implements them automatically where safe and refuses to share anything else across threads, so data races become compile errors. Rc is neither; Arc is both. (Section 14.2.)

How does async work in Rust?

async fn returns a future, a value describing work that does nothing until awaited. The standard library has no runtime to drive futures; Tokio is the usual choice. tokio::join! runs futures concurrently, like asyncio.gather. Use async for I/O-bound work with many waits, threads for CPU-bound work. (Section 14.4.)

What does unsafe do?

An unsafe block allows a few operations the compiler cannot check, such as dereferencing raw pointers or calling C functions. It does not turn the borrow checker off for ordinary code. Safe wrappers around small unsafe cores are how the standard library builds Vec and Mutex. Application code rarely needs it.

What are macros? Why does println! have a "!"?

Macros generate code at compile time. println! checks its format string against its arguments during compilation; vec! builds a vector; #[derive(Debug)] writes trait implementations. The ! marks a macro call as different from a function call.

What are zero-cost abstractions?

High-level features that compile to the same machine code you would write by hand: iterator chains become plain loops, generics become specialised functions, and Option<&T> takes no more space than a pointer. You do not pay at run time for code you do not use. (Section 12.4.)

Why would a Python team use Rust?

For CPU-bound hot spots and for tools where speed and reliability matter. PyO3 and maturin build Rust code into a Python extension module, which is how pydantic-core and polars work. Tools such as uv and ruff are Rust programs. The trade-off is a slower edit-compile cycle and a steeper learning curve.

How would you test this code?

With Rust's built-in test framework: #[test] functions run by cargo test, unit tests in a #[cfg(test)] module beside the code, integration tests in tests/. Inject collaborators through constructors or generics so a test can pass a simple version, as the order tests pass NoDiscount. (Section 15.8.)

18.3  Reading Unfamiliar Rust Code

  1. Open Cargo.toml: the edition, the dependencies (they tell you the stack: tokio, axum, serde, sqlx), and [workspace] members.
  2. Find the entry point: src/main.rs and its fn main, or src/lib.rs for a library. The mod lines list the modules.
  3. Read the types before the functions: structs, enums and traits are the design. An error enum lists everything that can go wrong.
  4. For a function, read the signature first. &self, &mut self or self tells you whether it reads, changes or consumes; a Result return tells you it can fail.
  5. Follow the ?s: each one is a place the function can return early with an error.
  6. In a web service, find the Router: it lists every endpoint and its handler.
  7. Read the tests. Test names state the intended behaviour in plain words.
  8. Run cargo doc --open for a browsable view of every public item.
